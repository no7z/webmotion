# Audit matrix

Record pass, fail, not applicable, evidence, viewport, and chapter for every checkpoint.

| Area | Checkpoint |
|---|---|
| Composition | Contract topology is recognizable at first view and across chapters |
| Interaction | Wheel maps to the intended state progression in both directions |
| Interaction | Smooth scrolling has no long trailing tail, duplicate controller, or CSS interpolation conflict |
| Interaction | Proximity snap leaves positions outside its threshold unchanged and aligns eligible chapters inside it |
| Interaction | Pointer behavior supplements rather than blocks browsing |
| Occlusion | Headings, body copy, controls, and subject remain intentionally layered |
| 3D meaning | State changes explain content, material, function, or narrative |
| Continuity | Position, rotation, scale, lighting, and camera do not jump at boundaries |
| Mobile | Reading order, subject path, type scale, and controls are recomposed |
| Mobile | Touch inertia remains native and any scroll-end snap uses the same bounded proximity rule |
| Accessibility | Keyboard, focus, contrast, alt/fallback, and reduced motion work |
| Accessibility | Reduced motion disables smooth-scroll and automatic snap controllers |
| Runtime | No console errors, missing assets, sustained jank, flashes, or layout shifts |
| Recovery | Resize, refresh mid-page, reverse scroll, and asset failure remain usable |

## Report

Include environment, URL, commit or build identity, viewports, template/version, adapter, required-gate result, objective defects, subjective review items, evidence paths, and retest status.
